[Arena-1](https://github.com/RM-Arena/Arena-1) 的独立策略分发仓库。
支持在线策略更新的客户端会在启动后及运行期间每 15 分钟检查更新，
也可以在策略库点击「检查更新」。用户无需安装 Git、登录 GitHub 或重新下载安装包。


当前策略库要求 **Arena-1 v0.7.0-beta.1 或更新版本**。`claude_opus55_xhigh_*` 策略由 **Claude Opus 5.5 xhigh** 编写，覆盖 2026 与 2027 两个赛季；其他作者保持各自署名。此次更新同步更名策略目录、展示元数据与归档内容。

**GPT-6.1-Sol-Max · 三叉戟进化 2027** 已加入策略库：2712 / 305 / 305 / 2763 / 2772，保留三台串联腿。重型锚定基地，步兵守前哨关联卡，机动步兵沿端部坡道与公路外侧绕后；返场重新越障，接防、免费配给与金币统一调度。版本 `c74822a475af24c3` 在当前源码引擎、双方统一该阵容、完整420秒换边的16局固定种子对照中15胜1负，零策略错误，决策耗时p99不超过14.6ms；唯一败局控制度差0.3。安装版0.7.2-beta.3另测1胜1负，不与当前引擎成绩混计。详见[源码与战术卡](strategies/RMUC2027/GPT/GPT-6.1-Sol-Max-team)及[完整评测记录](benchmarks/gpt61_sol_max_2027.json)。这些是开发与验证对照，不能视作独立赛事胜率，也不能证明胜过尚未公开的正式模型。

## 发布策略

1. 在 `strategies/<赛季>/<模型厂商>/<策略名称>/` 新增或修改完整提交：`manifest.json`、策略 `.py` 源码，
   以及可选的 `showcase.json`、`profile.json`。例如
   `strategies/RMUC2027/Claude/Claude-Opus5.5-Xhigh-team/`。赛季目录必须与 manifest 的
   `rules_profile` 一致（`RMUC2026` 或 `RMUC2027`）；厂商目录按模型系列命名（`Claude`、`GPT`、
   `Gemini`、`DeepSeek` 等，人工编写用 `Human`，来源不明用 `Unknown`）；策略目录建议写成
   `<模型>-<打法或模式>`，只能使用字母、数字、`.`、`-` 和 `_`。
2. 策略代码改动后，用 Arena-1 的提交工具重新生成 manifest，保证源码哈希与版本正确。
   新版 Arena-1 提交时会把训练时的战场参数写入 manifest 的 `battle_settings`，客户端据此
   在战场参数不同时提示。仅修改展示文件时不需要重新计算代码版本。
3. 将改动 push 到 `main`。GitHub Actions 自动校验源码、生成不可变 ZIP 与 `catalog.json`，
   并提交生成文件。工作流成功后，客户端下一次检查即可收到更新。不需要创建 Release。

本地也可以使用 Python 3.10+ 预览发布结果，无第三方依赖：

```sh
python publish.py --tracked
```

先 `git add` 新文件，再运行带 `--tracked` 的发布命令。
PR 可以先运行 `python publish.py` 检查，但未合并到 main 的策略不会分发。

## 文件结构

```text
strategies/<赛季>/<模型厂商>/<策略>/  策略源码、提交清单和展示文件
strategies/ids.json   目录到客户端策略 ID 的映射（保留已有策略的 ID）
publish.py            可独立运行的发布工具
library.json          最低客户端版本
catalog.json          客户端读取的发布索引（自动生成）
bundles/<sha256>.zip   以内容哈希命名的策略快照（自动生成）
```

客户端用策略 ID 识别策略：发布包内仍是 `strategies/<ID>/` 的扁平结构，所有已发布的客户端都能读取。
已有策略的 ID 记录在 `strategies/ids.json`，移动目录时同步修改这里的路径即可，ID 不变，
内置版本覆盖与 Elo 记录也不受影响。新策略不需要登记，ID 自动取 `<策略目录>_<年份>`
（去掉 `.` 等字符，如 `Gemini-38-Flash-blitz_2027`），但目录发布后不要再改名。

同 ID 的在线策略覆盖客户端内置版本；用户自己上传的策略独立保留。
下载或校验失败时客户端继续使用已有缓存与内置策略。更新不修改安装目录，
旧快照会保留以支持正在进行的比赛。删除在线策略后，客户端仍可能显示同名内置后备版本。

客户端会检查下载大小、SHA256、归档路径、源码语法、提交版本、规则版本及展示文件。
下载仅用于存储，策略在用户选择比赛后才会通过原有策略执行器运行。
如果新策略依赖新的 SDK、规则或引擎功能，请提高 `library.json` 的 `min_client_version`；
旧客户端会继续使用已有策略，并提示需要升级应用。

现有不含在线更新功能的安装包需要升级一次，之后策略可独立更新。
只有客户端引擎、界面或 SDK 功能变化时才需要新的 Arena-1 安装包。
